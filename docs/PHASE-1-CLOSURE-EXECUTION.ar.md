## المسار 1 — نطاق محدد بدل دورات اختبار مفتوحة

أُضيف `tests/browser/document_workflow.py` إلى مسار المتصفح الحقيقي الحالي الذي يعمل
بالعربية والفرنسية/الحاسوب والهاتف، في Development ثم Production HTTPS. يُعاد استخدام
مدير النظام والقارئ المالي الموجودين في fixture الميزانية دون حسابات أو دخول أو منح إضافية.
التنفيذ محصور صراحة في قواعد CI المؤقتة، ويرفض قواعد المؤسسة وأهداف المعاينة الأخرى.

الشريحة الجديدة تتحقق من:

1. رفع ملف نصي اصطناعي فعليًا (201)، مع قطع GET التالي وحده عمدًا؛ ليست محاكاة عطل بنية تحتية.
2. إظهار إقرار نجاح الرفع وفشل القراءة معًا، ثم إعادة قراءة حقيقية دون تكرار POST.
3. قراءة API مستقلة: سجل جديد واحد فقط وبصمة SHA-256 مطابقة.
4. البحث بالوصف، والتصنيف الذي لا يطابق، ومسح التصفية.
5. تنزيل الواجهة ومطابقة بايتات الملف، وعدم الانزياح الأفقي.
6. قارئ مخوّل موجود: تنزيل دون ظهور نموذج رفع، ودون طلب تعديل.
7. فتح `/admin/users` و`/organization/parties` مباشرة بحساب بلا صلاحياتهما:
   ظهور الرفض، وعدم تركيب جدول أو نموذج في main، وعدم إرسال طلب قراءة المحتوى المحمي.

النتيجة المحلية لحارس الهدف: **2/2**، وليست نتيجة متصفح. التنفيذ الفعلي الجديد
**نجح في CI46136503184 الخاص بـPR297**. ينتج JSON وPNG في artifacts العادية؛ لا ندّعي
استيراد الصور أو مراجعتها بصريًا. الاختبارات المكوّنية التسعة في PR296 تبقى أدلة
مستقلة للقفل المتزامن والمسودة والنتائج القديمة وتبديل اللغة، لا بديلًا عن المتصفح.

## المسار 3 — جمع أدلة المضيف بدل افتراض جاهزيته

الأداة الجديدة `scripts/collect-phase1-host-evidence.py` تجمع **ملاحظات للقراءة فقط على Linux**:

- HTTPS موثوق عبر اسم المضيف الحقيقي دون تزوير Host أو X-Forwarded-Proto، ولا `--insecure` ولا تتبع redirects.
- جاهزية `/health/ready`، والترويسات المحددة، وغياب جلسة المعاينة عبر GET، وعدم إتاحة Origin أجنبي للقراءة غير الموثقة.
- حالة تشغيل وتمكين خدمات التطبيق وCaddy ومؤقّتَي النسخ والتحقق باستخدام استعلامات systemctl فقط.
- صلاحيات ملف البيئة وpassfile باستخدام stat فقط دون قراءة محتواهما أو source أو تسجيل أسرار.
- وجود mount خارجي منفصل عن قرص النسخ المحلي، وتشغيل مدقق البصمة والحداثة الموجود اختياريًا.

لا تنشئ الأداة جلسة دخول، ولا تعدّل خدمة أو قاعدة بيانات، ولا تنفذ ترحيلًا أو استعادة.
المخرجات معرفات ثابتة ونتائج فقط؛ لا أسماء مضيفين أو مسارات محلية أو كوكيز أو سجلات.
`OBSERVED_PASS` تعني ملاحظة محددة لا اعتماد المهمة. تظل `phase1Acceptance=NOT_GRANTED`
حتى لو نجحت كل الملاحظات؛ تُذكر بوابات القبول البشري والتشغيلي غير المنفذة دائمًا.

### تشغيلها على مضيف المؤسسة بواسطة المشغّل المخوّل

نفّذها محليًا على Linux المستهدف، من إصدار المستودع المعتمد، باستبدال القيم حسب التثبيت.
لا ترسل كلمات مرور أو connection strings في المحادثة. الأداة لا تطلبها.

```bash
umask 077
python3 scripts/collect-phase1-host-evidence.py \
  --base-url https://promogest.lan \
  --ca-file /path/to/trusted-lan-ca.pem \
  --passfile /path/to/protected.pgpass \
  --check-backup-freshness > /secure/operator-evidence/phase1-host.json
```

يجب أن يكون مجلد المخرجات الآمن موجودًا قبل الأمر. رمز الخروج 0 يعني نجاح جميع
الملاحظات فقط، و1 يعني FAIL/NOT_RUN ويجب مراجعة JSON، و2 خطأ تشغيل/استخدام.
عدم تشغيل بعض الفحوص لا يتحول إلى PASS. اختبار الأداة محليًا بملفات وردود اصطناعية
ليس تنفيذًا على المضيف الفعلي. Windows يستخدم إجراءات PowerShell الموجودة؛ لا تغطيه هذه الأداة.

## المتابعة البرمجية المحددة — عزل تحميل الموظفين عن المشاريع

عولج اقتران طلب دليل المشاريع بطلب قائمة الموظفين: تأخر/فشل قائمة الموظفين لا
يخفي المشاريع السليمة ولا يبقي مؤشر تحميلها. لنافذة الصلاحيات حالة تحميل وخطأ
وإعادة محاولة مستقلّة بالعربية/الفرنسية. إعادة المحاولة لا تعيد استعلام المشاريع
ولا تنفذ كتابة، ويظل الإسناد معطّلًا حتى اختيار موظف نشط غير نظامي من القائمة
الحالية. تغيّر الحساب/نسخته/صلاحية قراءة الموظفين يغلق نافذة الوصول ويلغي النتائج
المتأخرة، دون توسيع أي صلاحية أو تغيير API.

التحقق المحلي: 159/159 حالة، TypeScript والبناء وحارس lint ناجحة؛ منها أربع
حالات مكوّنية جديدة AR/FR. التحقق البعيد لهذه المتابعة ما زال مطلوبًا، ولا تحوّل
هذه النتائج القبول البصري أو المؤسسي إلى Done.
