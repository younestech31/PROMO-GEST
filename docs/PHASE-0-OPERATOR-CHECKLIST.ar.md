# ورقة التنفيذ اليدوي: التهيئة الأولى والخروج

هذه ورقة عمل فارغة لحالتي `P0-A01` و`P0-A04` في [بروتوكول القبول، §4 و§5A](PHASE-0-MANUAL-ACCEPTANCE.md). انسخها لكل جلسة مراجعة. لا يُملأ اسم المُختبِر أو النتيجة مسبقًا. [اختبار Chrome الآلي بعد الدمج](https://github.com/younestech31/PROMO-GEST/actions/runs/44654878332) دليل مساعد وليس تنفيذًا يدويًا أو إذنًا بالإطلاق.

**قبل البدء:** سجّل النسخة (`git rev-parse HEAD`)، واسم المُختبِر، وتاريخ الجلسة وتوقيتها، ونظام التشغيل، واسم المتصفح وإصداره. جهّز أربع قواعد PostgreSQL 18 مؤقتة منفصلة، واحدة لكل سطر أدناه، بعد تطبيق الترحيلات وإنشاء الأدوار الأساسية، دون مؤسسة أو مستخدمين. استخدم واجهة React المتصلة بخادم ASP.NET Core الفعلي وحساب تشغيل منفصل عن حساب الترحيل. **توقّف إذا تعذّر إثبات أن القاعدة مخصّصة للاختبار. لا تمسح قاعدة موجودة، ولا تستخدم المحاكي.**

### تشغيل جلسة معزولة على جهاز المختبِر

من تشغيل GitHub Actions الناجح للنسخة المراد اختبارها، نزّل المرفق `phase0-manual-linux-x64`. على **Linux x86-64** مع Docker Engine محلي، وBash وPython 3 وOpenSSL وcurl، فكّ ZIP ثم الأرشيف الداخلي:

```sh
tar -xzf phase0-manual-linux-x64.tar.gz
cd phase0-manual
bash start-session.sh ar-desktop
```

افتح عنوان `127.0.0.1` الذي تطبعه الأداة في متصفح على الجهاز نفسه، واترك الطرفية مفتوحة. لا تحتاج إلى تثبيت .NET أو إدخال بيانات اتصال. يُنزَّل `postgres:18-alpine` في المرة الأولى. يتحقق المشغّل من خلوّ القاعدة قبل إظهار الرابط. استخدم `counts` في الطرفية لمعاينة أعداد المؤسسة والمستخدمين وتعيينات المدير؛ سجّل النتائج ونسخة البناء المعروضة. بعد حفظ الأدلة اكتب `quit` لحذف حاوية الجلسة وبياناتها المؤقتة. **لا يمكن استئناف هذه الجلسة بعد إيقافها.**

كرّر الأمر مع `fr-desktop` و`ar-mobile` و`fr-mobile`. كل تشغيل يبدأ بقاعدة جديدة؛ اسم الوضع للتوثيق فقط، وعليك اختيار اللغة والمقاس في المتصفح بنفسك. استخدم نافذة خاصة جديدة وأغلق جميع نوافذ التصفح الخاص بين الجلسات لتجنّب مشاركة ملفات الارتباط. لا تشارك الرابط على الشبكة ولا تستخدم الحزمة للنشر. اجتياز اختبار تشغيل الحزمة في CI لا يملأ أي خانة قبول يدوي.

**من هاتف عبر Codespaces:** شغّل `bash start-session.sh ar-mobile --private-forward` في طرفية Codespaces الخاصة. يحوّل المشغّل الوضع تلقائيًا أيضًا عند `CODESPACES=true`. افتح فقط منفذ التطبيق الجديد من **Ports → Private → Open in Browser**. اكتب `token` في الطرفية التفاعلية نفسها، وانسخ الرمز إلى خانة **رمز التهيئة** في المعالج. ليس كلمة مرور المدير؛ لا ترسله في المحادثة ولا تُصوّر الطرفية. لا تُحوّل منفذ قاعدة البيانات. لا يمكن تفعيل الرمز بأثر رجعي في جلسة محلية قديمة: افحص `counts` واحفظ الملاحظات أولًا، ثم استخدم `quit` إذا كنت مستعدًا لحذف قاعدة تلك الجلسة التجريبية وابدأ جلسة جديدة.

### في كل جلسة

1. **التهيئة:** افتح نافذة متصفح نظيفة واضبط اللغة والمقاس المحدّدين. تحقّق من ظهور معالج التهيئة. أدخل مؤسسة ومديرًا وهميّين. بعد الحفظ توقّع `201`، ثم شاشة الدخول مع اسم المؤسسة وإشعار الإتمام باللغة المختارة، لا جلسة مدير مسجّلة تلقائيًا. قبل الدخول، يجب أن يعيد `/api/auth/me` الحالة `401`.
2. **منع التكرار:** أعد إرسال طلب تهيئة صالح في بيئة الاختبار نفسها، قبل تسجيل الدخول، مع حماية CSRF العادية. توقّع `409 SETUP_ALREADY_INITIALIZED`؛ الرفض بسبب بيانات غير صالحة أو CSRF ليس دليلًا على منع التكرار. تحقّق من الأعداد أدناه ثم سجّل الدخول صراحةً بالمدير الذي أنشأته.
3. **الخروج غير المؤكّد:** وأنت في صفحة محمية، احجب طلب `/api/auth/logout` مؤقتًا من أدوات الشبكة في المتصفح، ثم اضغط «خروج». يجب أن تظل الجلسة ظاهرة، مع تحذير باللغة المختارة وزر لإعادة المحاولة. تحقّق من بقاء `/api/auth/me` متاحًا (`200`).
4. **الخروج المؤكّد:** ارفع الحجب واضغط إعادة المحاولة. توقّع `204` ثم شاشة الدخول. أعد فتح `/admin/users` وحدّث الصفحة: لا يظهر محتوى محمي، و`/api/auth/me` يعيد `401`. تحقّق أيضًا في عميل اختبار مستقل يحمل **الجلسة الوهمية نفسها** من قبل الخروج أنها كانت صالحة (`200`) وصارت مرفوضة (`401`). لا تُدرج قيمة الجلسة في أي محضر. إذا لم تُنفّذ هذه الخطوة يدويًا فسجّلها كخطوة متبقية، لا كنجاح يدوي اعتمادًا على CI.

استعلام قراءة فقط؛ الأعداد المتوقعة **0 / 0 / 0** قبل التهيئة و**1 / 1 / 1** بعد المحاولة الثانية:

```sql
SELECT (SELECT count(*) FROM organization_settings) AS organizations,
       (SELECT count(*) FROM users) AS users,
       (SELECT count(*) FROM user_roles u JOIN roles r ON r.id = u.role_id
        WHERE r.code = 'SYSTEM_ADMIN') AS admin_assignments;
```
